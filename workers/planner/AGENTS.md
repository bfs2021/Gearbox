# G3 Planner (the team's board of cards)

- Not released yet. `apps/planner` is a plugin-based UI like Schedule's (the shared top bar and theme) with two pages, **Board** (`/`, `src/plugins/board/`) and **Admin** (`/admin`, mentors and admins; `apps/planner/README.md`); `workers/planner` (Hono, Drizzle, D1 `PLANNER_DB`) has the API below.
- **What it holds** (migration `0002`, which dropped `0001`'s empty placeholder; `src/db/schema.ts`): `cards`, each with a title (1–200 characters), a `status` (the column: `not_started`, `in_progress`, `done`; `STATUSES`) and a `sort_order` within its column (gaps are fine; a move renumbers the column it lands in). `card_members` (migration `0003`): who's on each card, by G3ID user id, deleted with its card (foreign key, cascading). No dates or anything else yet.
- **Who changes it:** everyone signed in reads the board; everyone but a kiosk (`requireOAuthSession`) adds, renames and moves cards, and puts **only themselves** on a card or takes themselves off. **Only G3ID admins delete cards** (`requireAdmin`; `/me`'s `isAdmin` shows the trash button beside Add me on each card, and Delete in a card's dialog). `/me` returns `canEdit` (false for a kiosk), which hides the page's controls.
- **API** (`src/routes/cards.ts`): `GET /cards` (every card, with `memberIds`), `GET /cards/people` (the team's active members' names, from G3ID), `POST /cards { title }` (always at the bottom of Not Started, where every card starts; 201), `PATCH /cards/:id { title }`, `PUT /cards/:id/move { status, index }` (into that column at `index`, 0 the top, past the end the bottom), `PUT|DELETE /cards/:id/members/me` (the caller on or off; twice is still once), `DELETE /cards/:id` (admins only).
- **Meeting overviews** (`src/lib/overview.ts`, migration `0004`): mentors and admins choose a channel on the Admin page (`/admin`, `apps/planner/src/plugins/admin/`; `GET`/`PUT /settings { overviewChannel }`, `planner_settings`, one row per team, logged with `logTeamChange`) and choose **Send meeting overview** on the board (`POST /overviews`, in `DEMO_BLOCKED`; `GET /overviews/latest` for "Last sent"). It's posted with `postTeamMessage` and kept up to date with `editTeamMessage` (`@g3/auth`, through G3ID): after every change to the board (`afterChange` in `src/lib/cards.ts`, in `waitUntil`, and after `/gb-add`) `updateOverview` rebuilds the team's **latest** overview's text (`overviewText`, a pure function) and edits it only if the text changed (`overviews.last_text`). It lists Not Started and In Progress with who's on each card; every card listed is remembered (`overview_cards`), so one moved to Done since shows crossed off (`~~…~~`) and a deleted one goes. Titles and names go through `plainChatText` from `@g3/slack`. It always fits one Discord message (1,900 characters; long sections end "…and N more"). An edit that fails is logged and the next change tries again. Older overviews stop updating.
- **`/gb-add`** (`CHAT_COMMANDS` in `@g3/auth`): `POST /internal/teams/:teamId/commands/gb-add { userId, text }` from the platform, after G3ID found the member from their Slack or Discord; adds the card at the bottom of Not Started under their name (`addCard`) and answers `{ reply }`. Setup on Slack and Discord: `docs/deploy.md`, "Slash commands".
- **Syncing:** the page polls `GET /cards` every 5 seconds while it's visible, and after each change, skipping a poll during a drag or while a change is on its way, so an old answer never undoes what's on screen. No live push (that would take Durable Objects, a new Cloudflare product: ask the owners first). Two people moving cards in the same column at once: the last move wins, and the next poll shows everyone the result.
- Ports: app 5188, worker 8799 (inspector 9241). Icon: a clipboard with a checklist (`apps/planner/public/favicon.svg`, also `apps/portal/src/assets/app-icons/planner.svg` and the platform's docs icon), with the PNGs and `.ico` drawn from the same shapes.
- In the app library for every team, with a `preview` warning (`src/manifest.ts`); not switched on for any team (no platform migration; switch it on by hand in dev), and not on the platform's public home page or the issue forms' app list yet.
- **Not on Cloudflare yet**: production's D1 `database_id` in `wrangler.toml` is a placeholder and staging's says it isn't created. Before it deploys: `wrangler d1 create g3-planner-prod` (paste the id), `pnpm staging:create` (staging's database and placeholder Worker), then migrate.
- Text boxes use the demo's `task` kind (`packages/demo/src/safe-text.ts`). The demo's board (`src/demo.ts`) has a few cards in each column.
- Team-scoped: every table carries `team_id`, and every query goes through `inTeam`/`withTeam` (in the tenancy lint). It has delete, move, export and demo hooks (the platform's `PLANNER` binding, `TEAM_TABLES` in the schema, children first) and `test/isolation.test.ts`. `test/cards.test.ts` covers adding, moving, renaming, deleting, who's on a card and kiosks; `test/overview.test.ts` the overview's text, the channel, sending, updating and `/gb-add`. Who's on a card is in the privacy policy's app table. A new table goes in the tenancy lint, `TEAM_TABLES` and the isolation test's `TABLES`; a new route that takes a body gets one in the isolation test's `bodies`.
